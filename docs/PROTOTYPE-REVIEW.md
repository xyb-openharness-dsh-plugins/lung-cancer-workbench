# HTML 原型审核记录

日期：2026-10-17。本文先记录 [肺癌工作台原型 v1](prototype/lung-workbench-v1.html) 的静态审核，再记录 [小肺宝工作台原型 v3](prototype/lung-workbench-v3.html)，最后记录当前版本 [v4](prototype/lung-workbench-v4.html)。以下审核是结构/静态交互审阅，不是视觉实机、患者可用性或临床审核。

## 结论

原型已从场景展示页推进为可操作的设计样稿：十个病例/任务入口、肺癌相关低负担记录表、一图秀时间/轨道筛选、可点选指标点、键盘可达水平翻面、问题草稿和信息来源状态都有对应行为。主要场景与规格的结构关系基本一致，但它尚未实现真实资料解析/来源回链、保存持久化、患者联系号码或临床安全内容。因此不能把 HVT 判为通过，也不能当作可发布患者产品。

## 原型 v4 更新（当前样稿）

### 本轮修的三处硬问题

- **布局变形**：前版的栅格在内容列宽不足时会把中文挤成逐字竖排、卡片互相压叠；logo 引用指向原型目录之外，`file://` 下取图失败也加剧塌陷。v4 把所有栅格轨道改成 `minmax(0,1fr)`、工作区子项加 `min-width:0`、表格统一进 `.table-wrap`，指标翻面卡由绝对定位改为同一网格叠层（`grid-area:1/1` + `backface-visibility`），logo 复制到 `docs/prototype/assets/brand/` 并加 `onerror` 兜底。
- **临床检索丢失**：v3 只剩一个内嵌筛选框，看不出“自带登记库 + 多通道”。v4 新建顶层「临床试验」页：6 个通道卡（内置登记库可用并显示 28 条 = 2026 快照 14 条 + 历史登记 14 条，ClinicalTrials.gov API / Veeva CTV / WHO ICTRP / ChiCTR / CDE 均标“待配置”）、8 项筛选条件、结果表通栏、详情模态（含“与我的资料对照”，只列缺项、不打匹配分）、收藏、“怎么读登记信息”和检索边界说明。关闭本地库且其他通道未授权时给专门空态：**不是“没有相关试验”，而是“当前没有可查询的数据源”**。
- **配置窗口未体现**：v3 的“配置”只有一屏说明。v4 改为六分区设置：资料目录 / 文档解析（MinerU）/ 临床数据（通道授权）/ AI 与隐私（授权、留存、导出）/ 显示与无障碍（主题、大字、对比度、减少动效）/ 关于（版本、构建日期、边界声明）。

### 两个补齐的一级模块

- **营养支持**（二级：当下困扰 / 进食与体重 / 建议与回顾，见 v4.1 调整）：只做记录与回看，不生成热量、配方或补剂建议；“已经拿到的专业建议”区分来源与日期；体重用独立刻度、单点不连线。
- **心理支持**（二级：当下感受 / 我的记录 / 支持资源 / 私密话题 / 照护者自己）：记录默认私密，**不进一图秀、不进摘要、不进导出、不进 Agent 上下文**；“允许在复诊提纲里出现”是单独勾选，默认不勾；照护者情绪可单记，不写进患者档案主叙述。

### v4.1 补齐（同一晚，对齐乳腺癌 v0.3 的模块密度）

按用户对照意见（乳腺癌 `prototypes/v0.3` 的 `#nutrition`、`#mind`、`#review` 更完整）追加三处：

- **营养支持三级内容重排**：二级改为「当下困扰 / 进食与体重 / **建议与回顾**」。第三页不再是单纯的问题列表，而是「专业建议原文档案（日期＋来源＋适用条件）＋我的营养问题＋三件事分开回顾（吃了多少 / 为什么吃不下 / 体重）」。建议只抄原文，工作台不改写、不换算热量；来源不明的建议不给录入口。
- **心理支持加「照护者自己」二级**（现为 5 项）：照护者记录与患者记录同库不同身份，**不合并成患者的情绪症状**，默认不进提纲；页内给耗竭信号、三件可执行的小事，以及“患者档案共 N 条、其中 M 条属于照护者”的口径说明。
- **新增一级「收藏与回顾」**（二级：我的收藏 / 已保留结果 / 问题清单 / 报告与任务），与「复诊准备」分工：复诊准备是编辑台，收藏与回顾是陈列柜。要点：
  - 收藏的临床试验从试验页真实联动，可取消；界面明确“收藏不等于报名、不代表符合条件”。
  - **保留的提纲是快照**：点「保留这一版」后固定当时的问题数、资料数与覆盖范围，之后改问题清单不会改这份快照；删除只删这一份。
  - 问题清单区分「想问的事」与「我的看法 / 担心」，后者标注“不是医生结论”，导出时单独分区。
  - 报告只做 Markdown 预览（内容是真实拼出来的），PDF/图片标“未接入”，不伪装可用；另有“下次带什么”出门核对清单与 Agent 发送范围预览（按钮禁用）。

### 本轮验证（脚本，非人工视觉验收）

- 内联 JS `node --check` 通过；本地资源引用仅 `assets/brand/lung-care-logo.png`，落盘后可解析。
- 4 个模拟病例 × 31 个页面/子页组合渲染扫描（含 v4.1 新增的 6 个页面）：无 `undefined` / `NaN` / `[object Object]` 文本，无渲染异常。
- 10 个一级页 × 五档宽度（1440/1180/1024/900/780）= 50 个组合：页面级横向溢出 0，卡内溢出 0；900px 下试验结果表曾把“操作”列挤出卡外（表 738px / 容器 608px），已改为按宽度分级收列（类型→地区/开始），现表宽收进 608px、无卡内横滚。
- 390px 手机宽度 10 页均无页面级溢出。
- 交互链路（设置六分区、多通道检索、详情、收藏、营养记录、建议原文、心理记录、照护者记录、指标翻面、深色、切换病例、咯血流程、记录表单、症状弹窗、放疗表单、对比度、大字、问题库、提纲预览、**保留提纲、导出预览、写“我的看法”、出门清单**）全部成功，控制台无报错。

**仍未做**：真实浏览器视觉走查与读屏/触控验收、Desktop 宿主 `customFrame`、真实资料解析与持久化、真实通道授权后的在线检索、临床审核。所有病例、日期、检验值仍是虚构演示，不能作为医疗内容引用。

## 原型 v3 修复与功能审核

### 设计对照

已从本地源码对照 ovarian-workbench `docs/prototype/workbench-v3.html` 的工作区布局，以及 breast-cancer-workbench `prototypes/v0.3/index.html`、`app.js`、`style.css` 的左侧导航/患者上下文/顶部状态/分页面渲染/对话框模式。乳腺癌参考页的 live 浏览器状态未能通过浏览器安全策略检查；本轮对照来自用户指定目录中的本地原型源码。

### 已覆盖的原型交互

- 名称“小肺宝”，使用本项目已保存的用户 logo 与天蓝/肺部橙色系；可切换四个模拟病例，其中包含 NSCLC 术后、NSCLC 靶向、SCLC 放化疗和新确诊/等待结果。
- 工作区按任务分成看板、一图秀、病情整理、临床与用药、照护与症状、复诊准备、来源与试验，采用侧栏导航和档案上下文。
- 指标翻面卡改为明确的块级全宽容器，正反面独立水平翻转，避免窄内容列导致中文逐字竖排。
- 临床试验搜索嵌入 SQLite 快照 14 条记录，支持按 SCLC/NSCLC、阶段、招募状态及关键词筛选，并可跳转登记来源。
- 顶栏“配置”打开设置窗口，展示内置数据库、待接入 Veeva/WHO ICTRP/ChiCTR/中国药物临床试验登记、资料目录状态和隐私说明。
- 一图秀支持 3/6/12 月动态筛选，多指标同时选择、独立刻度、治疗/影像/穿刺事件筛选、点位详情和每卡独立水平翻面。
- 肺癌路径包含穿刺→病理→分子检测、分期原文、手术/靶向/放疗记录；SCLC 显示独立的放化疗/免疫/脑部沟通问题，没有默认套用 NSCLC 靶向路径。
- 胸腔操作、术后活动、症状、放疗进度有单独页面入口；复诊问题可选择、编辑、删除并预览。
- 模拟记录会暂存于页面内存并添加到一图秀事件；刷新会清空。
- 顶栏支持浅色/深色主题切换和大字模式；提供窄屏布局与减少动效设置。

### 本轮验证与限制

内联 JavaScript 通过 `node --check`；HTML 结构读取未发现重复 ID，已确认 logo 引用、亮/暗主题、窄屏断点、减少动效、临床数据库数据条数和筛选控件结构。页面尚未进行浏览器视觉验收、触控/读屏走查、Desktop 宿主运行或患者测试。所有日期、检验值和病例信息均为虚构演示；无本地文件读取、持久化、在线试验检索、DSH/AI 接入，也不提供真实医疗联系号码。

## 按 HVT 与规格检查

| 检查项 | 结果 | 证据/限制 |
|---|---|---|
| 术后活动自述 | 结构覆盖 | 可保存日期、活动变化、气促自述；明确自述非肺功能检查、单项可存。仅内存演示，无真实复测历史 |
| 胸腔穿刺/引流 | 结构覆盖 | 可重复提交、类型/日期/侧别/量/性状独立，缺项可存；尚未展示源文档关联ID |
| 免疫治疗症状回顾 | 结构覆盖 | 多选/自由文本，明确不判断 irAE；未配置真实治疗事件引用；清单标成不完整 |
| 咯血求助入口 | 安全边界基本符合 | 有血性痰记录和联系配置状态提示；没有拨号/真实联系方式，也没有分诊级别；正式部署前本地临床审核是阻塞条件 |
| 一图秀多指标 | 交互演示 | 指标按当前场景生成选择项；独立小图、刻度和时间范围；全部曲线数据是合成演示，不是患者检测记录 |
| 时间范围/事件轨道 | 交互演示 | 3/6/12月和全部切换会改变曲线采样窗口并筛选事件；部分事件日期是样例数据，不覆盖真实日期精度/时区 |
| 指标点详情 | 交互演示 | 鼠标和Enter/空格可查看模拟值；详情不回链真实来源，文案已说明未附真实文件 |
| 指标卡翻面 | 符合布局意图 | 左右 `rotateY(180deg)`，每张独立；文本型/未记录指标不绘制假曲线；背面数据明确为示意 |
| 样本/变异/放疗/术后病理 | 场景和提示覆盖 | 页面中有对应任务和来源状态说明；未实现真实四态流转、知识卡条件过滤、放疗符号图例和手术字段编辑 |
| 键盘/减少动效/窄屏 | 代码层部分符合 | 按钮和点可键盘操作、焦点样式、减少动效媒体规则、窄屏单列。实际焦点顺序、屏幕阅读器、大字及触控尺寸须实机走查 |

## 本轮已修正

- HVT新增的4类场景不再只是说明卡，增加了可提交的示例记录表；所有写入仅保存在页面内存，不上传、不持久化。
- 让指标选择器随病例变化；文本型状态不再被当作数值绘图。
- 指标卡仅对数值演示记录提供翻面，显式标注模拟值/模拟曲线；文本自述显示普通信息卡。
- 一图秀点位支持鼠标和键盘查看模拟详情；日期范围同时筛选事件；影像开关只影响影像事件。
- 将“查看原始报告”改为来源状态提示，不再假装有可打开文件。
- 补齐场景/范围按钮的 `aria-pressed`、44px最小操作高度、13px以上说明文字和键盘焦点样式。

## 仍需修复/验证

1. **真实临床内容封锁：** 咯血、免疫治疗相关症状、术后明显气促等提示在临床审核前不得发布为行动建议；当前原型只表达设计结构。
2. **患者数据真实链路：** 把表单接到领域模型/源记录ID/版本/隐私控制/持久化后，重新检查同日重复引流、纠错与导出。
3. **样本与治疗状态：** 当前任务摘要不等于状态机；送检中/待出/不足/失败四态、知识条件和放疗计划/实际图例需要真实组件。
4. **原型数据真实性：** 图表趋势为合成数列；不得被截图误当患者走势。进入下一版前可改用显著的“交互演示数据”水印并避免使用临床真实值范围。
5. **实机视觉审核：** 由于本地 `file://` 预览被浏览器安全策略拒绝，本轮没有视觉确认。不能以源码/语法检查代替桌面、宿主、窄屏、大字、色彩对比度和屏幕阅读器检查。
6. **HVT复评：** 完成原型逐屏走查与临床内容审核后，按HVT-5重新评估五层覆盖；目前只做了静态追踪，未运行 HVT 扫描脚本。
