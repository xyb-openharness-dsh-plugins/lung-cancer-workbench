# 开发阶段前置工作审查

审查日期：2026-10-17。范围：设计冻结、业务规格、现有工作台骨架、验收基线与肺癌试验 SQLite 快照。不是临床指南审查，也不是代码安全或 Desktop 兼容性认证。

## 结论

**可以开始受控的工程基线和无临床建议的垂直切片；还不具备完整患者产品开发/发布条件。** 用户与场景方向已明确，v4.1.0 原型已冻结，肺癌核心实体和 API 草案覆盖较广。工程开工前仍需锁定目标 Desktop 合同、建立源码基线、把 v4 转成可追踪的实现 parity，并确定首片的可执行数据/迁移方案。可与这些工作并行开展患者任务走查和医学来源审核。未获临床审核的提示、用药解释和急症内容不得作为正式患者建议上线。

设计冻结只指页面和交互样稿：[`PROTOTYPE-FREEZE.md`](PROTOTYPE-FREEZE.md) 记录了原型路径、SHA-256 与边界。它不等于需求、临床安全、宿主功能或发布验收签字。

## 已确认 / 已有证据

- 用户群体为肺癌患者和照护者；目标覆盖 SCLC/NSCLC 全病程，优先治疗与复诊准备；设计参考和品牌 Logo 已由用户确认。
- v4.1.0 有 10 个一级模块、27 个二级页，并覆盖患者情境、配置、临床试验搜索、收藏与回顾；版本和冻结 hash 见 [`PROTOTYPE-FREEZE.md`](PROTOTYPE-FREEZE.md)。
- 概念数据模型覆盖报告版本、取材/标本、病理/分子、治疗、病灶、胸腔操作、照护、收藏快照与导出；API 草案覆盖主要写命令和读模型。
- `npm run check` 通过；v4.1.0 内联脚本通过 `node --check`；数据库 `integrity_check=ok`、重复 NCT 编号为 0、14 条均有登记来源 URL。
- 试验快照数据统计见 [`reference/trials/README.md`](../reference/trials/README.md)。SQLite 是 14 条；v4 另有 14 条原型历史示例，不能把 28 条当成爬取数据库的记录量。

## 患者功能与发布前闸门

1. **患者/照护者任务验证（功能设计前优先）**：目前研究文件明示未访谈、未做可用性测试；草稿核对、家庭分工、个人数据分享和信息负担仍是假设。建议对刚确诊/等分子结果、治疗中、SCLC 照护者等不同任务做小规模走查。需记录任务是否完成、误解、额外输入量和改动决定；不能把原型自测当患者验证。
2. **临床来源与专业审核（面向患者的临床内容上线前阻塞）**：中国现行 CSCO/NHC 完整指南与版本，逐药 NMPA 说明书/伴随诊断/适用条件及地区可及性仍未逐项核对。咯血、气促、胸水、免疫治疗症状等联系文案需呼吸/肿瘤临床人员审核。未审核前只开发不带治疗方向的记录/来源/问题整理结构，临床提示保持禁用或明确为来源待核。
3. **AI/隐私授权（接入文件解析或模型前阻塞）**：明确哪些文件会离开本机、服务接收方/保留、用户授权撤回、密钥存储和日志脱敏；无网/无模型仍可保存和查看。v4 的设置是演示状态，不能当成真实安全控制。
4. **临床试验来源（产品化检索前阻塞，普通离线搜索可先做）**：当前 SQLite 仅是非穷尽发现快照；v4 试验页另外带 14 条未经本轮数据库核验的历史展示条目。先确定 MVP 是仅离线快照还是要在线多通道；若接入，定义来源授权、API/页面更新、地区/招募地点、快照时效、NCT 去重/冲突及来源回链。Veeva CTV 是发现入口且其页面称数据源为 ClinicalTrials.gov，不能据其计为独立注册库；Veeva OpenData Clinical 也不是同一个产品。
5. **可访问性与真实运行**：v4 结构和脚本检查通过，不等于完整视觉走查。首次完整 Tab 实现后须在实际目标宿主、窄宽、大字、键盘、读屏、减少动效、错误/空数据状态核验。按真实操作记录修正，不以静态 HTML 通过替代。
6. **发布与品牌**：`VERSION` 不存在，`package.json` 的 `0.1.0` 仍为脚手架值，v4 的 `4.1.0` 是设计原型版本，两者没有自动一致机制。未发布状态应保持清楚；对外发布前还须确认 Logo 授权、license/鸣谢、市场对数据库随包分发的限制和版本校验。

## 推荐开工顺序

1. Git 基线与冻结样稿归档；确认首片是离线、本机持久化且不发送患者信息的模拟到真实数据链路。
2. 核验目标 DSH Desktop 加载、customFrame 和本机存储合同；先装一个最小 hello-workbench，证明真实加载。
3. 完成页面 parity、首片 schema/migration/API/隐私决策和 AC01–AC43 的状态清理。
4. 患者任务走查并修订交互；同步开展临床来源准备，不让未审核医学建议进入产品。
5. 实现一个端到端垂直切片及其失败/取消/恢复验收，再扩展到 SCLC 对等骨架和其它模块。
