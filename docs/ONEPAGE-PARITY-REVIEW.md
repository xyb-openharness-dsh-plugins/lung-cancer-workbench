# 一图秀一致性评估

日期：2026-10-18。以下对照表保留为 RC8 历史差距记录。开发者已确认参照版本为 v4.1，随后指定采纳卵巢癌时间线细节。当前增量设计为 [v4.2 HTML](prototype/lung-workbench-v4.2.html)，自检证据见 [v4.2 审核记录](PROTOTYPE-v4.2-REVIEW.md)。新版尚待开发者确认，不能据此宣称已安装的 Desktop RC8 达到新版一致性要求。

## 用户问题与体验路径

预期路径：进入一图秀 → 选择档案及指标 → 调整时间范围 → 联合回顾检验、影像、取材与治疗 → 查看来源 → 返回原图。

当前实现具有指标卡、独立 SVG 曲线、指标勾选和记录列表，但整体结构比现存原型明显简化。添加模拟资料可填充已有图表，不能补齐缺失的时间范围、事件筛选、治疗轨或来源详情。现阶段不符合项目高精度原型一致性的验收要求。

## 具体代码缺陷

1. **翻回正面失效**：翻面正向写入 `flipped[label]`，背面按钮写入 `flipped[name]`。有数据时 label 包含名称、单位及方法，与 name 不同，因此背面按钮不复位当前卡片。
2. **可比性分组未闭合**：虽然 `metricKey` 包含名称、单位和方法，默认选择仍使用名称；曲线过滤 `metricKey(m) === selected || m.data.metricName === selected` 会把同名不同单位/方法的记录合并成一条曲线。不能以“已有独立纵轴”证明可比性正确。
3. **近期值受插入顺序影响**：先 `slice(-8)` 再按日期排序，卡片 latest 使用 `rows.at(-1)`；补录旧报告会导致最新值或图表窗口选错。
4. **空白值可被解释成零**：`Number('')` 和 `Number(' ')` 为 0，数值过滤只检查有限数，未显式拒绝空字符串；日期未知的数值也可能进入曲线并按序号落点。
5. **病程事件缺少私密范围过滤**：右侧对全部 records 调用 recordItem，症状及标为 private 的记录也会进入列表；与原型心理记录默认不进一图秀的边界不一致。这里是本机展示问题，未证明发生上传。

证据入口：`lib/client.js` 中 `timelinePage`（约 378 行）；原型 `docs/prototype/lung-workbench-v4.html` 中 `chartPanel`、`lanes`、`flipCard`、`timelinePage`（约 1768–1965 行）及 `pointModal`。

## 动效判断

应用代码有 0.45 秒 Y 轴翻面及减少动态效果的媒体规则，不能说“完全没有翻面”。但返回状态键错误和固定 absolute 布局使其不能视为完成原型交互。现存 v4 曲线采用静态 SVG；在找到 v5 之前，不把“曲线生长动画”擅自列为 v5 要求，也不能声称已经达到其动态效果。

## 验证与限制

已核实 Desktop `web` profile 安装版本为 `0.1.2-rc.8`，已安装客户端与项目文件逐字节一致。`npm run check` 通过；这只证明语法/静态包合同，不证明视觉和交互一致。用户截图是 RC6 空档案状态，不能作为 RC8 有数据时的视觉实测。未修改产品代码、重启 Desktop 或宣称达到 98%。

## 后续验收顺序

先取得 v5 原型并冻结具体文件/版本，再按同一病例、相同指标和时间窗、相同工作区尺寸截图；先补布局、时间窗/事件/治疗轨和交互闭环，修复分组/翻面/来源问题，再评估字号、间距、颜色及动效。验收至少覆盖两套病例、零/单/多条指标、补录旧记录、不同方法/单位、未知日期、翻面返回、键盘和右侧 AI 打开后的窄工作区。
