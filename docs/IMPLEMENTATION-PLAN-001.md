# 实施计划 001：有来源的肺癌诊疗事件记录

状态：进行中。开发分支：`codex/records-slice`。设计合同：冻结的 v4.1.0，见 [原型冻结记录](PROTOTYPE-FREEZE.md)。

## 首片范围

实现不依赖 DSH UI 的领域内核，让患者/照护者可将取材、病理/检测、治疗及复诊相关事件整理为可回溯记录。肺癌特别字段保留标本与检测之间的关系、组织/血浆来源、检测项目状态、原文、日期精度和用户核对状态。SCLC 与 NSCLC 共用事件载体，但不得自动互相映射。

本片不上传文件、不解析病历、不调用 AI、不提供治疗决策、不写目标路径、不声称持久化或 DSH 已接通。持久化适配器须待目标 Desktop 的目录授权和运行时合同实测后再加。

## 实施步骤

1. 建立本地 Git 基线并保留冻结原型及公开试验数据快照。
2. 实现纯领域函数：校验、追加、版本冲突、来源与用户复核状态；旧版本只增不改。
3. 用 Node 内置测试覆盖正常/边界/错误路径，尤其是未知日期、未检/待检/失败/样本不足和计划/实际分离。
4. 暴露稳定导出，不耦合 UI/DSH；更新任务状态、实现 parity 和 API 待核边界。
5. 完成静态检查、单元测试、原型冻结 hash 复核，并提交切片。

## 完成证据

- `npm test` 通过；`npm run check` 通过。
- 记录保存包含原始来源、主体、时间精度和核对状态；更正会形成新版本。
- 未核对记录不会变成已接受事实；计划不会显示为实际完成。
- DSH、资料目录、数据库/恢复、视觉呈现仍标记未验证。
