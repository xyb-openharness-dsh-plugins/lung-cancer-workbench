# 小肺宝 · 指标趋势 Tab 项目适配

2026-10-20。规范：[分类与3D卡片设计](24-METRIC-TREND-TAB-DESIGN.md)。开发者已要求参考两图编制设计与HTML，**v4.2.7的最终视觉/交互尚待开发者确认**。此次原型内容不计作RC13生产功能完成。

| 项目 | 小肺宝口径 |
| --- | --- |
| 入口 | 病情整理→指标检测；页内Tab采用资料库/整理草稿·核对/病情档案/指标检测/病情汇总 |
| 肺癌特有页面映射 | 原诊断与分期、取材与检测移入病情档案的两个独立区块，保留原入口别名 |
| 分类唯一来源 | 原型`docs/prototype/metric-trends-v427.js`中的MT_GROUPS/MT_CATALOG；指标页与新一图秀选择器共用 |
| 分类目录 | 肿瘤标志物5项、血常规4项、肝功能2项、肾功能与电解质2项、炎症与感染相关1项、营养相关1项、身体测量1项，共16项；不是检查推荐 |
| 空卡策略 | 已记录卡优先；未记录项目可展开，次要空组默认折叠，标题仍给完整目录项数 |
| 3D | 两列、700px以下单列、276px固定卡高、1100px透视、480ms rotateY、每卡独立；减少动效直接终态 |
| 前次比较 | case+metric+unit+method+laboratory同组；可比信息不齐不算差值/不连线；箭头不表示好坏 |
| 来源与报告表 | 原型是明确标记的合成来源；同日期/同模拟报告聚合，参考区间缺失写未转录；实际产品按documentId+revision聚合 |
| 原型候选流程 | 手工补录→整理草稿/核对→核对并纳入→指标卡和一图秀使用同一观察列表；只保存在页面内存，刷新清空 |
| 生产SQLite现状 | clinical_records保存metric记录，date_json/source_json/data_json/review_json保留日期/来源/数值/审核；documents/document_candidates保存原件和候选；尚未把本轮分类卡片读模型接入RC13 |
| 生产字段映射 | data.metricName/rawValue/unit/methodText/laboratoryText；日期/参考区间/报告修订和别名标准化需在实施前逐项核验，不能因JSON可保存就称读模型能力已完成 |
| 未知日期/文本值/同日多次 | 通用规范覆盖；本轮HTML手工补录要求有效日期+数值，文本/未知日期交互尚未扩展，列为后续生产验收项 |
| 临床分级 | 本轮不新增阈值、异常着色、疗效判断；已有分级规范需另行来源审核与确认 |
| Desktop发布范围 | RC13仅交付密集病程遮挡曲线修复；本轮分类指标卡片属于待确认HTML，不自动标成生产已实现 |

HTML：[v4.2.7](prototype/lung-workbench-v4.2.7.html)，打开后进入病情整理→指标检测；可用 `?profile=p3#metrics` 查看SCLC已有指标，`?profile=p4#metrics` 查看未记录状态。hash与自检见 [v4.2.7审核](PROTOTYPE-v4.2.7-REVIEW.md)。

2026-10-20开发者补充确认：自动按指标类型分类，每个可比序列一张3D反转卡；序列内按采样时间排序。正面最近值，背面历次趋势；不按日期平铺多张卡，不以上下展开代替翻面。v4.2.7当前实现的`mtSeries()`进行时间排序，`MT_CATALOG/MT_GROUPS`进行类型归组，`.mt-card-inner`使用preserve-3d与rotateY。

2026-10-20确认：一图秀指标选择只显示简称，单位/方法/机构移到悬停与可访问名称；完整分组身份不变。原型和生产选择区同步为紧凑两列。


## RC15 生产落地更新

开发者已用实际应用截图明确要求实施本模块。当前实际目录唯一来源为`lib/metric-catalog.js`（10类）；分类卡片与一图秀菜单共用`categorizedMetricSeries()`，读取原有已确认SQLite记录。保守按原指标名/单位/方法/机构保持可比身份，别名用于归类，不静默合并记录。新`lib/client-metrics.js`负责3D卡片。此前表格中的“尚未接入RC13”是历史状态，现以[RC15审核](RC15-GROUPED-METRIC-CARDS-REVIEW.md)为准；v4.2.7整版导航仍不等同于已实现。


## RC16：指标卡片与一图秀一致性补充（2026-10-20）

- 分类卡片与一图秀共用 `categorizedMetricSeries` / `selectedMetricSeries`；同日多条不猜先后、仅显示点，单位 / 方法 / 实验室分别分组，私密记录过滤一致。
- 一图秀底部3D卡片跟随当前选择（最多4项），不再固定展示资料中的前4组；简称只影响显示，不改变记录身份。
- 58项自动测试通过；实际客户端浏览器验收：110条合成病例产生11张276px卡片，独立点击 / 回车翻面；800px窗口单列、无页面横向溢出。1280px一图秀曲线位于可视区域。
- 浏览器环境是独立合成资料预览，不能代替DSH Desktop原生宿主验收。窄窗口一图秀控制区上下堆叠，需向下滚动查看曲线；未宣称全尺寸首屏可见。
- SQLite结构与临床数据库不变。安装证据见 `docs/reviews/rc16-desktop-install.json`；Desktop须开发者手动重启后验收。
