# 设计与实施分期 v0.2

日期2026-10-17。所有业务仍为待设计确认/未实现。全病程是最终覆盖，不代表要先做临床指南大全。

## D0 已完成：需求/方向起点

用户选择全病程且治疗/复诊优先，明确SCLC与NSCLC并要求针对指南/穿刺/转移/靶向药研究；社区starter初始化，优先读ovarian-workbench，加入Logo与色系。

## D1 本轮：可审阅规格包

SPEC、患者场景、知识范围、靶向药/用药、分期与治疗方式、转移再评估、四核心模块、领域模型/API、验收、追踪和来源状态。文档静态一致性待检查；临床内容审核/用户访谈尚未做。

## D2 原型验证与冻结

已完成并按用户要求冻结 `docs/prototype/lung-workbench-v4.html`（v4.1.0）；冻结 hash 见 `PROTOTYPE-FREEZE.md`。v4 沿用 ovarian v3 / breast prototype v0.3 的工作区信息架构，并有 10 个一级模块、27 个二级页、多通道临床试验搜索演示和六分区设置。页面有 28 条试验演示记录，其中仅 14 条来自 SQLite 快照。该阶段只冻结设计，不代表临床、用户或宿主验收通过。

## D3 开发就绪性审查（当前）

进入实现前补齐 Git 基线、目标 DSH/Desktop 合同、v4 parity 矩阵与首个垂直切片的 SQLite 可执行迁移/备份方案。患者任务测试及临床内容审核是对应患者功能/临床提示上线前闸门；不阻止独立的无患者数据技术 spike。详见 `DEVELOPMENT-READINESS-REVIEW.md`。

## D4 内容与合同

优先取得适用中国CSCO/NHC现行全文、逐药NMPA说明书/支付与院内信息。内容编辑/患者通俗性审读/肿瘤专业人员复核；版本和来源纳入资源管理。目标DSH API/runtime版本实机核验并冻结。

## D5 垂直切片实现

先完成用户目录/原件和版本化记录API；再实现“资料/穿刺→病理/检测→低负担草稿→复诊问题”端到端。其次完成治疗/变异知识源和用药记录以及SCLC相同层级骨架。并行确保营养、心理、日常安排不只留空入口。

## D6 多模块整合

指标、一图秀、转移部位回顾、试验检索/来源、Agent任务快照/导出。完整功能清单逐ID实现和核验，不把外链/模拟数据称为完成。实现过程中可按资源切完整Tab检查。

## D7 安装和实机

按starter流程核对包、版本/profile、Desktop渲染/原生会话、业务读写/导出；数据库迁移备份/恢复与升级验证。报告未见的状态为未验证。

## 后续增强

多设备/远程家庭协作、医院信息系统、自动指南同步、自动复查提醒/后台通知、DICOM影像量化属于增强，前置核验法律、接口/同意、临床安全与宿主支持。核心业务路径无这些服务也应能处理本地文档与问题。
