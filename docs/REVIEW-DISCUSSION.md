# 规格审读发现与讨论 v0.1

本轮将SPEC v0.1从简短占位扩写为肺癌专属设计包。审读基于参考项目结构、公开来源和用户明确要求；不是独立模型审查、临床审查或患者调研。

| 优先级 | 发现 | 本轮处理 | 未解决/影响 |
| --- | --- | --- | --- |
| 高 | 初版未区分SCLC/NSCLC与变异级治疗依赖 | 加病理/分期双路径、靶点/变异/检测/药物合同 | 中国现行逐药标签及CSCO全文缺失，不能上线药物建议内容 |
| 高 | 穿刺只当普通文件导入 | 增加Specimen、TestRun与标本流转/不足状态 | 穿刺行政流程内容需院方/患者验证 |
| 高 | 转移无部位/局部与全身治疗关系 | 增加按部位事件、治疗时间与再评估问题 | 影像比较与紧急症状文案需专业审核 |
| 高 | 药物名单容易被误读为治疗推荐 | 每药知识条目按地区/变异/阶段/前治/日期管理；美国批准与中国可及分离 | 本轮中国标签/医保未完成 |

| 中 | 参考SPEC模块广度可忽略肺癌独特治疗链 | 新增R/C子模块、实体/API；验收基线已扩展至AC01–AC43 | HTML原型已创建；浏览器视觉/宿主实机验收仍待完成 |

## 当前推荐

全病程导航有“新确诊/取材检测/治疗与用药/转移后再评估/日常支持/复诊”任务入口。治疗与复诊显著优先；病理和SCLC/NSCLC作为平行内容路径。暂建议“先看有来源草稿，再选择核对”，但希望用户就这一交互基线作决定后再冻结交互合同。

## 下一轮一项关键讨论

“系统先整理出有来源、明确未核对状态的短草稿，患者可跳过少量关键疑点，之后再决定是否写入正式档案”是否符合你希望的帮助方式？这会影响核对页面、一图秀与复诊导出的默认数据层。可接受后再用原型演示具体界面；若不认可则保留可选方案并更新SPEC。
