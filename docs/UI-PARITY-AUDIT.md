# DSH Desktop 与冻结原型 UI 差距审计

基线：冻结 [v4.1.0 原型](prototype/lung-workbench-v4.html) 与 DSH Desktop 实机 `0.1.2-rc.2`；本次修改候选 `0.1.2-rc.8`。审计依据包括原型 DOM/CSS、当前客户端渲染代码，以及 `2026-10-18` DSH Desktop 1228×768 实际截图（今天页和照护与症状页）。原型是带模拟档案的独立页面；实机没有档案。比较时不得把原型假病历或指标复制到真实 UI。

## 观察到的差距

| 优先级 | 现状 | v4.1 合同 | 用户影响 | 改进 |
| --- | --- | --- | --- |
| P0 | 无档案时首页只显示一张“还没有资料档案”卡；截图下方约 60% 区域为空 | 首页仍有欢迎区、任务入口、接下来、最近病程、档案关键信息、缺口、复诊问题和一图秀摘要 | 首次打开像未完成的空壳；不知道从哪里进入穿刺、病理、靶向/用药、放疗或试验 | 首页始终保留原型信息架构；空档案以明确的“未记录”呈现，不填入模拟事实 |
| P0 | 有档案时也只有病例概况、待核对、最近病程和 4 条入口 | 8 个任务入口、未来安排、最近病程、病情要点/缺口/问题清单、多指标摘要 | 关键肺癌病程场景需要靠侧栏逐页猜测，缺少每日概览 | 扩展为 8 个具名入口和真实资料驱动的双栏首页 |
| P1 | 照护与症状空态只显示一张空列表卡 | 原型有具体症状任务、症状记录/联系路径、术后活动、胸腔操作与免疫治疗相关入口 | 空状态无下一步，未提供场景入口 | 统一空态模板，提供场景化快捷动作和安全边界文案 |
| P1 | 工作台嵌入 DSH 后出现宿主全局栏 + 工作台导航，视口比独立原型窄 | 原型是一套 248px 工作台导航 + 顶栏 + 内容区，内容最大宽 1520px | 工作区变窄、左侧导航层级增多 | 保留宿主原生导航；工作台内容区按宿主可用宽度响应式折叠内栏/网格，避免固定宽度和空白 |
| P2 | 工作台组件与原型语义相似，但图标、卡片密度、间距和标题区不完全一致 | 原型使用品牌色、8 个入口卡片、双栏内容及多指标卡片 | 整体看起来像功能测试页，未形成完整工作台 | 先收敛布局/内容层级，再统一图标、留白、字级与状态标签 |
| P0 | 实机工作台未提供右侧 DSH 原生会话区 | 工作台留在主区，AI-IDE 使用 DSH 原生节点；默认 35%，可调 25%–45% | 上下文无法在工作台和对话间安全衔接 | 接入原生 conversation、owner 核验、无损 splitter 和显式资料预览；细节见 [Agent Pane 设计合同](AGENT-PANE-DESIGN.md) |

## 首轮修改范围

已在 `0.1.2-rc.8` 候选中修复 P0 首页结构和无档案引导；以实际记录渲染摘要，只有真实档案存在的事实才显示值，未知字段显示“尚未记录”，不会从缺失推断阴性或治疗状态。之后逐页对照 v4.1 的 records、timeline、clinical、care、review、trials 和 settings 页面，按真实截图继续修复。

`0.1.2-rc.8` 还实现 DSH 原生 AI-IDE 右栏：默认关闭、35% 宽度、25%–45% 调整；620–760px 顶栏换行且导航保留文字。单独状态稿标注“非真实会话”。资料必须逐项选择、预览和同意；候选以及症状/照护/心理记录默认排除，原生草稿/附件/发送中时拒绝写入。原生对话渲染、桌面窄窗与宿主 owner 仍待 Desktop 实机验收。

首轮成功标准：

- 无档案首页包含欢迎/建档、8 个任务入口、病情要点、近期/最近记录、复诊准备和指标状态；临床试验入口保持可直接访问。
- 有档案首页能显示真实记录计数、候选/已确认状态和近期病程；无数据时不生成曲线或医学结论。
- 快捷入口有可用动作；需要个人档案的入口先引导建档，不静默失败。
- DSH Desktop 重启后首页内容无大块空白；窄宽、大字、深色仍可用。
- 单测只验证结构/行为，不代替 Desktop 真机视觉和用户验收；不得据单测报告 parity >98%。

演示数据验收：RC.8 提供两套明确标注的只读合成 NSCLC 档案，供激活看板、病理/分子/治疗信息与多指标趋势后对照 v4；演示记录不可导出、写回真实档案或作为 AI 档案上下文。实际视觉 parity 仍须在 Desktop RC6 加载后逐页核对。
