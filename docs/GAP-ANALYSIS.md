# 肺癌工作台设计差距分析 v0.1

日期：2026-10-17。审阅范围：肺癌 SPEC v0.2、CORE-MODULES、SCENARIOS、ACCEPTANCE、UI-DESIGN，与 `xyb-workbench/docs/design/TIMELINE-SPEC.md`、`DASHBOARD-SPEC.md`、`V3-FEATURE-INVENTORY.md`、`V2-V3-PARITY-AUDIT.md`、`prototype-v3.html` 及只读实现 `lib/client.js` 对照；并参照本项目所指的 ovarian-workbench 设计文档体系。参考项目只提供交互/规格组织参照，不把胰腺癌业务规则直接迁移为肺癌需求。

## 结论

肺癌 SPEC 的领域覆盖已经比上一版完整：NSCLC/SCLC双路径、取材/标本/病理/分子检测、靶向药、手术/放疗、转移复评均有条款。但它还是“应该支持什么”的文字清单，缺少把高频任务变成屏幕行为的页面合同。尤其没有可运行原型，也没有一图秀筛选、同时间窗事件联动、多指标阅读、指标卡翻转等交互定义。因此实现者仍可能做出通用癌症看板、用药清单式靶向页、以及只有静态折线的时间图。

## 对照差距

| 主题 | 参考项目已有证据 | 肺癌文档现状 | 差距/用户影响 | 修订要求 |
|---|---|---|---|---|
| 实际界面 | xyb 有可运行 prototype-v3 与独立设计规格；ovarian 有工作台原型 | 只有方向/token，无肺癌业务HTML原型 | 患者无法验证术语、页面顺序、任务入口 | 建立可交互 HTML，模拟资料明确标注；按场景审阅 |
| 一图秀定位 | 独立Tab；数据、用药/治疗事件、标注共用时间窗 | O01罗列轨道，缺布局和操作 | “一图秀”容易变成静态总结，无法复诊讲清时间关系 | 共同时间轴、范围预设、多个显示开关、点选来源、快照合同 |
| 多指标选择 | xyb 左侧指标清单可多选；所选项目同时间窗呈现 | O02只说卡片，M02只说趋势，未定义多选 | 指标多时拥挤；量纲/方法不同会误读 | 选择清单+已选摘要；多指标采用独立量纲的小图/小倍图；有条件比较才共享轴 |
| 动态控制 | 日期范围、关键点、治疗/变化显示切换，窗口缩放，点选详情 | 没规定动态行为或状态保留 | 页面“能画图”但筛选失效或每次重置 | 将日期窗口、轨道开关、缩放、选择点、空/单点状态写成验收项 |
| 指标卡翻面 | client.js `.xyb-metric-inner` 使用 `rotateY(180deg)`；每张卡独立aria-pressed；背面显示最近记录小图 | 当前只写“展开”，prototype缺位 | 容易被实现成上下折叠，丢失参考交互且卡片过高 | 明确左右翻面、独立状态、正反内容与窄屏降级；用户可键盘切换 |
| 肺癌治疗事件 | 肺癌文档有取材/手术/放疗/系统治疗的实体要求 | 没有把这些映射到时间轴视觉图例/事件卡 | 复诊最关键的“何时做了什么、依据哪份资料”不直观 | 取材、病理/分子待出、手术、系统治疗、放疗、影像和转移部位分别成事件，计划/实际区分 |
| NSCLC/SCLC可辨识 | 领域章节覆盖两类 | 时间图/原型没有病例分支 | 页面可能只覆盖EGFR晚期NSCLC，遗漏SCLC患者 | 原型包含NSCLC+SCLC切换；主导航等权入口，病种路径不互相套用 |
| 真实患者任务 | 场景文档列出了需求 | 没有把病例转成“患者下一步做什么” | 记录很多，但不知道先找什么或问什么 | 首屏任务卡按证据缺口呈现：等病理、样本不足/借片、手术后病理、靶向药复诊、放疗定位/分次、转移复评 |
| 图表医学误读 | xyb 明示趋势不是诊疗结论的限制 | 当前有“不推断疗效”条款，缺图表细节 | 同轴/断线/计划实绩可能造成因果和病情判断 | 无跨指标共轴暗示；数据来源、单位、方法、报告/采样日可见；图下注明不代表疗效判断 |
| 一致性验收 | 参考实现状态与规格有可追踪关系 | AC13泛化“ID/版本统一” | 无法检查交互与原型是否偏离 | 新增AC25-31，关联O/M/C场景和原型 |

## 肺癌患者可用性要求（本次纳入）

1. **从现实任务进入，而不是从疾病百科进入。**首页先回答“我现在在等什么/准备什么/要问什么”。手术、穿刺、靶向药、放疗是可直接打开的资料整理任务，不暗示患者自行选择治疗。
2. **把样本链条讲成人话。**展示“取材日期和部位 → 样本/病理号 → 病理 → 分子/PD-L1各项状态 → 下一步核对”，标本不足、组织/血浆差异、等待借片要能看懂；不把“未检出”翻成全阴性。
3. **治疗方式作为并行事实。**手术记录切除方式/日期/术后病理/切缘/淋巴结等原文；放疗记录部位、计划/已完成分次和来源；系统治疗记录方案名和具体药物、计划与实际。患者能看到这是“医生记录/我的自述/待核草稿”。
4. **靶向知识以变异为入口。**基因结果→检测样本/方法/报告日期→改变原文→药物知识条件→个人处方/问题。不能从单一变异直接宣称适用，也不把知识卡与当前处方混成一张卡。
5. **转移以部位和证据呈现。**脑、骨、胸膜/胸水、肝、肾上腺等报告分区；对比对象、报告描述和团队结论分层。局部治疗和全身治疗可在同一时间轴并行显示。
6. **低负担复诊准备。**用户可选时间段和重点，直接生成“已经确认 / 待核 / 想问医生”三栏；允许信息不足时带着明确缺口继续，不强迫补齐整个档案。

## 原型范围与明确边界

[`prototype/lung-workbench-v1.html`](prototype/lung-workbench-v1.html) 是设计验证原型，不是生产功能；数值、病历、日期和机构均为虚构演示数据。它验证患者首页任务、病例场景切换、NSCLC/SCLC差异入口、一图秀事件+多指标联动、指标卡水平翻面。它不提供诊疗建议，不模拟真实检测结论，不代表指南路径正确性。后续原型评审需要确认页面层级/内容/密度；临床知识条目仍须逐项来源审查。

## 尚未解决/不可冒充结论

- 未完成肺癌患者/照护者访谈或可用性测试；“下一步任务优先”是产品假设。
- 一图秀多指标是否默认小倍图、是否允许最多选择数、窄容器布局需用真实Desktop容器验证。
- 参考实现里部分颜色/事件呈现是否适用于肺癌、低视力用户和色觉差异仍需可访问性走查。
- 治疗路径具体内容、靶向药中国可及性与当前指南条目尚需取得全文并经临床审核；原型不承担验证。

## HVT复核补充（2026-10-17）

[HVT-REVIEW](HVT-REVIEW.md) 发现原规格在术后活动自述、胸水反复操作记录、免疫治疗症状回顾和咯血联系路径上有“有名词无页面/验收”的问题。现已将这些落到SPEC §4.6–4.7、SCENARIOS S09/S11/S12、CORE C08–C11、PleuralProcedureEvent、AC32–AC40和原型场景切换。咯血内容采纳“无AI/离线可快速打开联系入口”，拒绝“少量血丝等到常规复诊”；任何具体时限/分级须本地临床审核。原型已加术后、胸水、免疫和咯血入口，但尚未在浏览器中逐屏走查。HVT闸口仍未签字，见报告末尾处置表。
