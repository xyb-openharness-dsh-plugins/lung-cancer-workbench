日期：2026-10-27。基线：`docs/prototype/lung-workbench-v4.2.8.html`（本轮已由用户确认）。
包版本：`0.1.2-rc.18`。前置：RC17 已把疾病概要整页与状态卡接入 `lib/client.js`，但只做到「加一块卡」，没有处理它与看板原有内容的冲突。

## 本轮修掉的三件事

### 1. 看板出现两个「下一步」，结论互相矛盾

同一屏上下两块给出冲突信息：

| 位置 | 内容 |
| --- | --- |
| 状态卡（首卡） | `D+173 状态卡 · 暂无已记的安排` / `下次：尚未记录日期与事项` |
| 问候横幅 | `下一步 骨转移灶姑息放疗 30 Gy / 10 次` `2026-08-05 · 已确认` |

横幅取的是「最近一条已确认安排」，不判日期，把 **已经过去 80 多天** 的记录标成「下一步」。两块并存等于工作台自相矛盾。

按原型对齐：`function hero() { return statusCard(); }`——状态卡 **就是** 首卡。应用侧改成 `const hero = primerStatusCard()`，撤掉问候横幅；原来挂在横幅上的「不上传病历」「N 条演示记录」两个标签并入状态卡的档案信息行，信息不丢。

### 2. 「距下次 N 天」的天数符号反了

`dayOf()` 算的是 `今天 − 日期`。未来的安排代入后得到负数，却被当成「过去」，于是一条 2099 年的安排会渲染成「已过 26427 天，待更新」。改为取反后才是「还有几天」：

```js
const nextGap = next ? -dayOf(dayish(next)) : null
```

同时补两条断言锁住方向：未来 → `距下次「…」N 天`；日期已过 → 不出现「距下次」「已过」。日期已过的安排按「历史」处理，不再冒充下次。

### 3. 撤横幅后新用户丢了「浏览演示病例」入口

空态原来只有「＋ 建立本机资料档案」。改为同时给「＋ 建立本机资料档案」「浏览演示病例」，与撤横幅前的能力一致。

## 卡头补回事项名

原型卡头是「距下次<事项> N 天」，应用侧此前只写「距下次安排 N 天」。现按 `dataTitle(next)` 带入事项名；名称超过 14 字时退回通用说法，避免挤坏卡头。
