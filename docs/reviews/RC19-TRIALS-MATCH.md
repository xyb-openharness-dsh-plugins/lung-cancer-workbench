## 2. 分数怎么算（口径必须写死在界面上）

判据只有四类，全部来自**登记的结构化字段**与**档案里的已记录字段**：

1. **病理类型**（硬性）：登记组织学 vs 档案病理类型。不同 → 不符合。
2. **疾病范围**（硬性）：从登记标题推断（辅助 / 新辅助 / 围手术期 → 早期可切除；III 期巩固 → 局部晚期；一线 / 后线 → 晚期转移；局限期 / 广泛期维持 → 对应范围）。
3. **系统治疗线数**（硬性）：0 线（初治）或 ≥1 线（治疗后）。登记不限制时**不生成判据**，也不计入分母——「不适用」不算「待确认」。
4. **标志物**（硬性）：只对**明确作为入组标志物**的位点（EGFR / ALK / ROS1 / RET / MET / KRAS G12C / BRAF / HER2 / NTRK / PD-L1）逐位点对照。

```
符合度 = 符合项 ÷ 对照项（含待确认）
档位：硬性不符合 → 硬性条件不满足
      符合度 ≥ 80% 且待确认 ≤ 1 → 字段都对得上
      符合度 ≥ 55% → 部分对得上
      其余 → 需补充信息
```

**刻意不做的事**

- 药物靶点（DLL3 / B7-H3 / PD-1 / VEGF / IMP3）**不参与打分**：它们是药物打哪里，不是「患者必须具备的检测条件」。界面上在详情浮窗里单列「研究靶点」并注明这句。
- 入排标准原文、ECOG、器官功能、洗脱期、中心名额**不在本机快照里**，因此不生成判据，也不假装判过。浮窗的「入组 / 排除条件原文」区直接写「本机快照没有收录，请到官方登记页核对」，并给官方链接。
- 档位词不用「高度符合」：100% 只代表「登记字段都对得上」，用「字段都对得上」避免被读成入组资格。
- **病理类型待确认时不排名**（p4）：这时分数只会把「没记录」算成待确认，0% 附近看不出东西，反而像结论。改为显示「现在档案里有什么 + 补齐后才能对照的三件事」。

## 3. 交互

- 子页：`匹配 / 检索 / 收藏与跟踪`（沿用既有 `subnav`，`SUBPAGES.trials`）。
- 详情浮窗：右侧滑入（`min(580px, 94vw)`），遮罩点击、✕、`Esc` 三种关闭；关闭后焦点回到触发的按钮，页面与滚动位置不变（不 pushState、不改 hash）。
- 收藏：卡片上「收藏并跟踪 / 已收藏（在跟）」，收藏页可「标为准备问 / 归档 / 取消收藏」。
- 「把待确认项加进问题清单」：把该条登记的待确认判据写成一条问题，进 `p.questionList`（复诊准备页可见）。
- 偏好：只改排序与冲突提示（例如「没有中国大陆中心」），**不改变任何一条符合 / 不符合**。

## 5. 已知边界 / 待裁决

1. **疾病范围与线数是按标题推断的**（快照无结构化字段）。界面上每条都写「按标题推断，需核方案原文」。若接入 ClinicalTrials.gov 在线通道（`protocolSection.eligibilityModule` 有原文），可以把这两条换成入排原文逐条对照。
2. **检索页的排序也用同一套分数**，因此「与我无关」的条目会按 0–30% 排在后面；若希望检索完全按登记日期排、不带任何个人化痕迹，需要改。
3. 收藏状态（在跟 / 准备问 / 已归档）目前只有手工三态，没有「登记状态变化」时间线——快照里没有变更历史，做了就是编。
4. 演示数据的登记状态可能已变化（快照 2026-10-17）；历史登记那 14 条标了「状态待核」。

## 6. 应用层落地（0.1.2-rc.19）

`lib/client-trials.js` 重写，`SUBPAGES.trials = ['匹配', '检索', '收藏与跟踪']`。与原型相比的四处必要改动，都因为**应用侧的数据不是演示数组而是真快照**：

| 原型 | 应用侧 | 原因 |
|---|---|---|
| 手工给每条登记标 `line`（辅助/一线/后线） | `TRIAL_SCENES` 按**英文标题关键词**归类 | 快照只有 15 个结构化字段，没有治疗场景；805 条标题全英文 |
| 只有成规模的演示条目 | **匹配候选池**：按病理类型取最近 50 条，显示「50 / 469」并可继续载入 | 快照 805 条，`pageSize` 上限 50；不能假装全库扫描 |
| 档案是 `PEOPLE` 演示对象 | `trialFacts()` 从 `records` 派生（诊断/病理/分期/分子/系统治疗） | 应用侧只有记录，没有预置字段 |
| — | **反向对照**：登记写「Wildtype / 野生型」时判据方向反转 | 实测中把 "EGFR Wildtype" 的登记判成了「位点对得上」，是真错 |

另有两处口径收紧：

- **疾病范围两侧同词**：档案侧原来写「晚期转移」、登记侧写「晚期/转移」，同类永远落到「待确认」。统一为「晚期/转移」。
- **读不出就记待确认**：标题读不出疾病范围的登记，生成一条「待确认」判据。否则这类条目只剩病理一条判据，会拿到 100%。

三个待裁决点的处理（按 demo 落地，均可再调）：

1. **分数口径** → 先用四类结构化字段；接入 ClinicalTrials.gov 在线通道拿到 `eligibilityModule` 原文后，可把「疾病范围」「系统治疗线数」换成入排原文逐条对照。
2. **检索页排序** → **不做个人化**：按用户选的条件（开始日期 / 首次登记日期 / 编号 / 阶段）排序，分数只作卡片标注。这样「与我无关但存在」的条目不会被压到后面。
3. **收藏三态** → 手工三态（在跟 / 准备问 / 已归档）+ 收藏日期，不做登记状态变化时间线（快照没有变更历史，做了就是编）。存 `localStorage: xiaofeibao.trial-saved`，只存登记 id 与条目快照，不写档案库。
