# RC15 · 应用指标检测分类3D卡片

2026-10-20。开发者明确指出应用“病情整理→指标检测”仍是汇总表＋按时间堆积的记录列表，要求按类型组织3D翻转卡片。这次直接修改生产客户端，不仅修改HTML或文档。

## 实现

- 移除原“指标检测”汇总表、“按时间排列的指标记录”长列表及占用右栏的大段提示，改为全宽分类区域、桌面两列/窄内容区单列。
- 唯一分类目录在 `lib/metric-catalog.js`，包含肿瘤标志物、血常规、肝功能、肾功能与电解质、凝血、感染与炎症相关、营养相关、身体测量、心电与生命体征、其他已记录指标。按明确别名归类；未知名称保留在其他，PCT等歧义缩写不猜含义。目录单位仅是说明，不覆写报告单位，不增加检查记录。
- 指标卡与一图秀选择器共用分类读模型；一图秀选项仍只显示简称，完整名称/单位/方法/机构留在提示中。
- 一张卡对应一组已有的完整指标身份（原名称、单位、方法、机构）。正面最近值、同组前次变化、日期、次数、来源；背面真实日期轴/轻度平滑/数据点来源，以及可展开的时间序列记录。仅归类别名，不擅自合并原指标名称不同的记录。
- 每卡276px固定高度，480ms rotateY 3D翻面。每卡状态包含病例ID，互不影响；隐藏面aria-hidden/inert；键盘回车/空格可翻。来源点/记录按钮不冒泡；历史记录在卡内独立滚动，展开仍不撑高。大字使用340px固定卡高；系统减少动效切终态。
- 0值保留；文本结果不强转数值；未知日期保留在原始记录但不入轴；同日多次在当前日级轴不猜先后、不做前次差值。方法或机构未知只显示点，跨单位/方法/机构分组不连线。
- 来源仍走原有记录/原件回查，导入与核对沿用原API；SQLite schema与真实病历数据不改动。没有开启临床分级或异常着色。
