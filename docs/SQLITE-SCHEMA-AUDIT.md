# SQLite 病例 schema 能力核对

核对日期：2026-10-18。范围：肺癌工作台当前领域类型、SQLite 迁移、记录 API，以及两套合成病例的落库和回读。

当前 schema 能保存档案、来源、精度日期、审核状态和全部肺癌记录类型。记录按 `kind` 存放，`date_json`、`source_json`、`data_json`、`review_json` 保留结构化 JSON；病例、记录、审核决策使用关系表、外键、版本号和事务。手术、系统治疗、放疗、胸腔操作、穿刺样本、病理、分子检测、标志物、分期、转移病灶、指标、症状、照护事项与复诊问题都可在 SQLite 往返保存。新增测试以两套演示档案完整写入并重新读取所有字段，覆盖其实际使用的记录类型。

这表示**存储能力覆盖了当前界面模型**，不表示 schema 已经做到临床字段级别的完整约束。肺癌记录的细节主要放在 JSON 中；SQLite 层目前没有对 `kind`、JSON 有效性、各类必填键、标本与检测外键、转移部位、药物标准码、治疗线次、手术范围、放疗剂量/分割、TNM 子项或指标单位做字段级约束。领域层校验也只对部分类型做了严格检查（如 specimen、molecular_test、部分治疗状态、diagnosis 临床类型）；pathology、staging、biomarker、lesion、metric、symptom、care_task 和 visit_question 仍接受较宽松的 JSON 对象。

结论：当前 schema 足以支持本轮 UI 展示与可追溯记录存储；不应把它描述为已完成的临床数据标准模型。后续 schema 迭代应采用迁移，不破坏现有 JSON 记录；优先加入每种 `kind` 的领域校验和迁移测试，再评估将高频字段规范化为关系列/子表及 specimen 引用约束。任何临床字段标准化均需先由肺癌业务需求确认，不能从演示数据推断真实临床规则。
